# เชื่อม AI เข้ากับ List, Docs และ Wiki ผ่าน MCP

คู่มือนี้อธิบายวิธีให้ผู้ช่วย AI เช่น Claude Code, Claude Desktop, VS Code หรือ Cursor เข้าถึง T-Timeline ได้ ถ้าเปิดคู่มือนี้ในแอป ที่อยู่เซิร์ฟเวอร์ในทุกตัวอย่างคือที่อยู่จริงของระบบนี้แล้ว ถ้าอ่านจากไฟล์ใน repo ให้แทนส่วน origin ในตัวอย่างด้วยที่อยู่ของเซิร์ฟเวอร์ เช่น `https://pm.example.com` ส่วน `<secret>` คือ token ที่คุณสร้างเองในขั้นตอนที่ 2

Token หนึ่งอันเป็น **ระบบเดียว ใช้ได้ทั้งระบบ** ไม่ผูกกับ Wiki อีกต่อไป: เลือกได้ว่าจะให้ AI แตะโมดูลไหนบ้าง — **List** (งานในโปรเจกต์), **Docs** (เอกสารในโปรเจกต์) และ **Wiki** (คลังความรู้) — เลือกได้มากกว่าหนึ่งโมดูลในตัวเดียว

## 1. ระบบนี้คืออะไร

- AI เข้าถึงสิ่งที่คุณให้สิทธิ์ ผ่าน **MCP เท่านั้น** (endpoint `POST <origin>/api/mcp` แบบ Streamable HTTP, ชื่อเซิร์ฟเวอร์ `t-timeline`)
- ทุก token อ่านได้เป็นพื้นฐานในทุกโมดูลที่เลือก ส่วนการสร้างและแก้ไขต้องเปิดสิทธิ์เพิ่มทีละโมดูล ไม่มีการลบหรือ archive ผ่าน MCP ในโมดูลใดเลย
- token หนึ่งอันทำได้ **ไม่เกินสิ่งที่เจ้าของ token มองเห็นและทำได้อยู่ในตอนนี้** ระบบตรวจสิทธิ์ของเจ้าของใหม่ทุกครั้งที่มีการเรียก ถ้าคุณเสียสิทธิ์ในโปรเจกต์หรือ Wiki ใด token ก็ทำสิ่งนั้นไม่ได้ทันที
- token เข้าถึงได้เฉพาะโปรเจกต์หรือ Wiki ที่คุณติ๊กเลือกไว้ตอนสร้างหรือแก้ไข token — เลือกโปรเจกต์ครอบคลุมทั้ง List และ Docs ของโปรเจกต์นั้น ส่วน Wiki เลือกทีละอัน

## 2. สร้าง token

1. เปิด **Tokens / MCP** — จากแถบเมนูด้านซ้ายของหน้า Projects (หน้าแรก), จากเมนูบนสุดของ All Timeline, People และหน้า Profile หรือ Tokens เอง, หรือจากเมนู Wiki (ไม่ได้อยู่ใต้ Wiki คนเดียวอีกต่อไป แต่ยังเปิดจากที่นั่นได้)
2. กด **Make a token** แล้วเดินตามขั้นตอน
   1. **Modules** — เลือกโมดูลที่ token นี้จะใช้: List, Docs, Wiki (เลือกได้มากกว่าหนึ่ง)
   2. **Permissions** — แต่ละโมดูลที่เลือก อ่าน (Read) ติดไว้เสมอและปลดไม่ได้ ส่วน Create และ Write เลือกเพิ่มได้อิสระต่อโมดูล
   3. **Where** — เลือกโปรเจกต์ (ครอบคลุม List และ Docs) และ/หรือ Wiki ที่ token นี้เข้าถึงได้ มีปุ่ม **Select all** ต่อรายการ ซึ่งติ๊กเฉพาะรายการที่เห็น ณ ตอนนั้น โปรเจกต์หรือ Wiki ที่สร้างทีหลังไม่ถูกเพิ่มเองอัตโนมัติ ต้องกลับมาติ๊กเพิ่มเอง
   4. **Name and confirm** — ตั้งชื่อ (Label) ให้จำได้ว่าใช้กับเครื่องหรือโปรแกรมไหน เช่น `Work laptop – Claude Code`, เลือกวันหมดอายุได้ (ไม่บังคับ, ตั้งได้ตอนสร้างเท่านั้น) แล้วตรวจสรุปสิทธิ์ก่อนกด **Create token**
3. กด **Copy** เพื่อคัดลอก token ที่ขึ้นต้นด้วย `pmw_`

> **token จะแสดงเต็มเพียงครั้งเดียว** ระบบไม่ได้เก็บตัว token ไว้ จึงแสดงซ้ำไม่ได้ ถ้าทำหาย ให้ลบอันเดิมแล้วสร้างใหม่

แต่ละบัญชีมี token ที่ยังใช้งานได้พร้อมกันไม่เกิน 20 อัน การแก้ไข (Edit) token เปิด stepper เดิมซ้ำได้ทุกเมื่อ เปลี่ยนโมดูล สิทธิ์ และขอบเขตได้โดยไม่ต้องสร้าง secret ใหม่

## 3. Claude Code

รันคำสั่งนี้ใน terminal โดยแทน `<secret>` ด้วย token ของคุณ

```bash
claude mcp add --transport http t-timeline <origin>/api/mcp --header "Authorization: Bearer <secret>"
```

ตรวจว่าเชื่อมต่อได้

```bash
claude mcp list
```

บรรทัด `t-timeline` ควรขึ้นว่าเชื่อมต่อแล้ว (Connected) ใน Claude Code พิมพ์ `/mcp` เพื่อดูสถานะและรายการเครื่องมือได้

คำสั่งข้างต้นเพิ่มเซิร์ฟเวอร์ให้เฉพาะโปรเจกต์ที่เปิดอยู่ ถ้าต้องการใช้ในทุกโปรเจกต์ ให้เพิ่ม `--scope user`

```bash
claude mcp add --transport http --scope user t-timeline <origin>/api/mcp --header "Authorization: Bearer <secret>"
```

ถ้าต้องการลบออก ใช้ `claude mcp remove t-timeline`

## 4. Claude Desktop

Claude Desktop เชื่อมผ่านสะพาน `mcp-remote` ซึ่งรันด้วย `npx` จึงต้องติดตั้ง Node.js ไว้ในเครื่องก่อน

คำสั่งที่ Claude Desktop จะเรียกให้คือ

```bash
npx -y mcp-remote <origin>/api/mcp --header "Authorization:${WIKI_TOKEN}"
```

เปิดไฟล์ `claude_desktop_config.json` (ใน Claude Desktop ไปที่ **Settings → Developer → Edit Config** ได้) แล้วเพิ่ม `t-timeline` ใน `mcpServers` ตามตัวอย่าง แทน `<secret>` ด้วย token ของคุณ

```json
{
  "mcpServers": {
    "t-timeline": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "<origin>/api/mcp",
        "--header",
        "Authorization:${WIKI_TOKEN}"
      ],
      "env": {
        "WIKI_TOKEN": "Bearer <secret>"
      }
    }
  }
}
```

ใน `args` ให้เขียน `Authorization:${WIKI_TOKEN}` ติดกันโดยไม่มีช่องว่าง แล้วใส่คำว่า `Bearer ` ไว้ในค่า `WIKI_TOKEN` แทน เพราะช่องว่างใน `args` ทำให้บางระบบ (โดยเฉพาะ Windows) แยก header ผิด

ตำแหน่งของไฟล์

| ระบบ | ที่อยู่ไฟล์ |
|---|---|
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |

บันทึกไฟล์ แล้ว **ปิด Claude Desktop ให้สนิทและเปิดใหม่** (บน Windows ให้ออกจากไอคอนที่ถาด system tray ด้วย) จากนั้นเครื่องมือที่ token นี้มีสิทธิ์จะปรากฏในเมนูเครื่องมือของช่องแชต

**claude.ai บนเว็บ (Connectors) ยังใช้ไม่ได้ในเวอร์ชันนี้** เพราะ Connectors ต้องใช้การยืนยันตัวตนแบบ OAuth ซึ่งเซิร์ฟเวอร์นี้ยังไม่รองรับ เซิร์ฟเวอร์นี้รับเฉพาะ Bearer token

## 5. VS Code, Cursor และโปรแกรมอื่นที่รองรับ Streamable HTTP

โปรแกรมเหล่านี้เชื่อมต่อตรงได้ โดยไม่ต้องผ่าน `mcp-remote`

**VS Code** สร้างไฟล์ `.vscode/mcp.json` ในโปรเจกต์ (คีย์บนสุดคือ `servers`)

```json
{
  "servers": {
    "t-timeline": {
      "type": "http",
      "url": "<origin>/api/mcp",
      "headers": {
        "Authorization": "Bearer <secret>"
      }
    }
  }
}
```

**Cursor** แก้ไฟล์ `~/.cursor/mcp.json` (ใช้กับทุกโปรเจกต์) หรือ `.cursor/mcp.json` ในโปรเจกต์ (คีย์บนสุดคือ `mcpServers`)

```json
{
  "mcpServers": {
    "t-timeline": {
      "type": "http",
      "url": "<origin>/api/mcp",
      "headers": {
        "Authorization": "Bearer <secret>"
      }
    }
  }
}
```

โปรแกรมอื่นที่รองรับ Streamable HTTP ใช้ค่าเดียวกัน คือ URL `<origin>/api/mcp` และ header `Authorization: Bearer <secret>` ส่วนชื่อคีย์บนสุดของไฟล์ให้ดูจากเอกสารของโปรแกรมนั้น

## 6. เครื่องมือต่อโมดูล

เครื่องมือที่ขึ้นให้เรียกได้ขึ้นกับว่า token มีโมดูลและสิทธิ์อะไร อ่าน (Read) ติดมากับทุกโมดูลที่เลือกเสมอ

### List — งานในโปรเจกต์ (ครอบคลุมด้วยขอบเขต "โปรเจกต์")

| เครื่องมือ | สิทธิ์ที่ต้องมี | ข้อมูลที่ส่ง | ได้อะไรกลับมา |
|---|---|---|---|
| `list_projects` | อ่าน | ไม่มี | โปรเจกต์ที่ token เข้าถึงได้ พร้อม id, ชื่อ, slug และ role ของเจ้าของ token |
| `list_tasks` | อ่าน | `project_id` | ทุกงานในโปรเจกต์นั้นตามลำดับใน List: id, parentId, depth, name, estimateStart/End, actualStart/End, values |
| `read_task` | อ่าน | `task_id` | หนึ่งงาน ในรูปแบบเดียวกับ `list_tasks` |
| `create_task` | Create task | `parent_id`, `name`, ไม่บังคับ `after_id` | งานใหม่ |
| `update_task` | Write | `task_id` และฟิลด์ที่จะแก้ (ชื่อ, วันที่ประมาณการ/จริง, values) หรือ `parent_id`/`after_id` เพื่อย้าย (แก้กับย้ายแยกคำขอกัน) | งานที่แก้แล้ว |

Estimate และ Actual เป็นคนละฟิลด์กันเสมอ `update_task` เขียนเฉพาะฟิลด์ที่ส่งมา ไม่มีการคำนวณฟิลด์หนึ่งจากอีกฟิลด์หนึ่ง

### Docs — เอกสารในโปรเจกต์ (ครอบคลุมด้วยขอบเขต "โปรเจกต์" เดียวกับ List)

| เครื่องมือ | สิทธิ์ที่ต้องมี | ข้อมูลที่ส่ง | ได้อะไรกลับมา |
|---|---|---|---|
| `list_projects` | อ่าน | ไม่มี | โปรเจกต์ที่ token เข้าถึงได้ พร้อม id, ชื่อ, slug และ role ของเจ้าของ token |
| `list_docs` | อ่าน | `project_id` | เอกสารทุกฉบับในโปรเจกต์ |
| `list_doc_pages` | อ่าน | `doc_id` | หน้าของเอกสารนั้นตามลำดับการอ่าน |
| `read_doc_page` | อ่าน | `page_id`, ไม่บังคับ `include_rich_content` | หัวข้อ, เนื้อหาแต่ละ section เป็น Markdown |
| `create_doc` | Create doc | `project_id`, `title` | เอกสารใหม่ |
| `create_doc_page` | Create page | `doc_id`, `title`, ไม่บังคับ `markdown`, `parent_id` | หน้าใหม่ |
| `update_doc_page` | Write | `page_id`, `updatedAt`, เลือก `markdown` หรือ `rich_content` หนึ่งรายการ, ไม่บังคับ `section`, `title` | หน้าที่แก้แล้ว |

หนึ่งโปรเจกต์เดียวกันครอบคลุมทั้ง List และ Docs ของมัน; Defects (รายการข้อบกพร่อง) ไม่อยู่ในขอบเขตของ MCP เลย

### Wiki — คลังความรู้ (ครอบคลุมด้วยขอบเขต "Wiki" เลือกทีละอัน)

ชื่อเครื่องมือ **เดิมทุกตัว** ไม่เปลี่ยน client ที่ตั้งค่าไว้ก่อนหน้านี้ยังใช้ได้โดยไม่ต้องแก้อะไร

| เครื่องมือ | สิทธิ์ที่ต้องมี | ข้อมูลที่ส่ง | ได้อะไรกลับมา |
|---|---|---|---|
| `list_wikis` | อ่าน | ไม่มี | Wiki ที่ token อ่านได้ พร้อม id ชื่อ คำอธิบาย และจำนวนหน้า |
| `list_pages` | อ่าน | `wiki_id` | โครงหน้าของ Wiki นั้นตามลำดับในต้นไม้ |
| `read_page` | อ่าน | `page_id` หรือ `wiki_id` คู่กับ `slug` | เนื้อหาหน้าเป็น **Markdown**; แผนภาพ Mermaid เป็นซอร์ส |
| `search` | อ่าน | `query`, ไม่บังคับ `wiki_id`, `limit` (สูงสุด 20) | หน้าที่ตรงกับคำค้น พร้อมข้อความตัวอย่าง |
| `create_wiki` | Create wiki | `title`, ไม่บังคับ `description` | Wiki ใหม่ เป็นของเจ้าของ token เอง และเพิ่มเข้า scope ของ token ที่สร้างเท่านั้น |
| `create_page` | Create page | `wiki_id`, `title`, `markdown`, ไม่บังคับ `parent_id`, `slug` | หน้าใหม่ |
| `update_wiki` | Write | `wiki_id`, `title` หรือ `description` | ชื่อหรือคำอธิบายที่แก้แล้ว |
| `update_page` | Write | `page_id`, `updatedAt`, เลือก `markdown` หรือ `rich_content` หนึ่งรายการ, ไม่บังคับ `title` | หน้าที่แก้แล้ว |

ไม่ต้องเรียกเครื่องมือเอง พิมพ์ถามเป็นภาษาธรรมดาแล้ว AI จะเลือกเครื่องมือให้ เช่น

- "มีงานอะไรค้างอยู่ในโปรเจกต์ A บ้าง"
- "สร้างงานใหม่ชื่อ ... ใต้โมดูล ..."
- "สรุปหน้า การติดตั้งกล้อง เป็นข้อ ๆ"
- "ค้นใน wiki ว่าตั้งค่า NVR ยังไง"

### สิ่งที่ MCP ทำไม่ได้ ไม่ว่าโมดูลไหน

- ไม่มีการลบ, archive, restore, เปลี่ยนเจ้าของ, สมาชิก, ลิงก์สาธารณะ หรือ upload ไฟล์ ในโมดูลใดเลย
- การย้ายงานข้ามโปรเจกต์ไม่ได้ (ย้ายได้เฉพาะภายในโปรเจกต์เดียวกัน)
- การแก้ไข Docs หรือ Wiki ไม่มีทางทำให้ไฟล์แนบหรือลิงก์งานที่หน้าถือไว้หายไปเงียบ ๆ ระบบปฏิเสธการแก้ไขแบบนั้นแทน
- ก่อนแก้หน้า (Docs หรือ Wiki) อ่านด้วยเครื่องมืออ่านก่อนเสมอ แล้วส่ง `updatedAt` ที่ได้กลับไป หากได้ `E_DOC_CONFLICT` ต้องอ่านใหม่ก่อนส่งซ้ำ ระบบไม่เขียนทับงานผู้อื่นให้
- ถ้าหน้าใช้ rich content ให้อ่านด้วย `include_rich_content: true` แล้วแก้สตริง `rich_content` ที่คืนมาแทนการส่ง Markdown ที่เปลี่ยนไป ซึ่งจะถูกปฏิเสธเพื่อกันโครงสร้างสูญหาย ส่วนการส่ง Markdown เดิมกลับไปจะคง rich body เดิม
- เครื่องมือเขียนจะปรากฏเมื่อ token มีสิทธิ์นั้น Client บางตัวอาจต้องโหลดรายการ tools ใหม่ แต่ server ตรวจสิทธิ์ใหม่ทุกคำขออยู่เสมอ
- การเรียก create ซ้ำอาจสร้างรายการซ้ำ ไม่ควร retry อัตโนมัติเมื่อยังไม่ทราบผลครั้งก่อน

## 7. แก้ปัญหา

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| `401` | token ผิด ถูกลบไปแล้ว หมดอายุแล้ว หรือบัญชีของคุณถูกปิด ให้สร้าง token ใหม่ |
| `429` | เรียกเกิน 60 ครั้งต่อนาทีต่อ token (รวมทุกโมดูล) รอประมาณ 1 นาทีแล้วลองใหม่ |
| `Not found.` | token ไม่ครอบคลุมโปรเจกต์หรือ Wiki นั้น หรือคุณเสียสิทธิ์ไปแล้ว หรือเป็นรายการใน Defects ซึ่ง MCP เข้าไม่ถึงเลย |
| โปรเจกต์หรือ Wiki ที่ต้องการไม่ขึ้นในเครื่องมืออ่าน | ไปที่ **Tokens / MCP** กด **Edit** ที่ token แล้วติ๊กในขั้นตอน **Where** ถ้ายังไม่มีสิทธิ์ในโปรเจกต์หรือ Wiki นั้นเลย ให้ขอจากเจ้าของก่อน |
| เรียกเครื่องมือเขียนไม่ได้ | ต้องเปิดสิทธิ์ (Create/Write) ของโมดูลนั้นใน **Permissions** ก่อน และสิทธิ์ของเจ้าของ token เองต้องพอด้วย (เช่น Create doc ต้องการ Admin ของโปรเจกต์) |
| เชื่อมต่อไม่ได้เลย | ตรวจว่า URL ลงท้ายด้วย `/api/mcp` และค่า header ขึ้นต้นด้วย `Bearer ` (มีช่องว่างหนึ่งช่องตามหลัง) |

## 8. ความปลอดภัย

- **อย่า commit token ลง git** ไฟล์ `.vscode/mcp.json` และ `.cursor/mcp.json` ในโปรเจกต์มักถูก commit ไปด้วยโดยไม่ตั้งใจ ให้เพิ่มลง `.gitignore` หรือใช้ไฟล์ระดับผู้ใช้แทน
- ใช้ **token หนึ่งอันต่อหนึ่งเครื่องหรือหนึ่งโปรแกรม** เมื่อเครื่องหายหรือเลิกใช้ จะลบได้เฉพาะอันนั้น
- ให้สิทธิ์และขอบเขตเท่าที่จำเป็น — ไม่ต้องเลือกทุกโมดูลหรือทุกโปรเจกต์ถ้าไม่ได้ใช้
- **ลบ token ที่ไม่ใช้แล้ว** ที่ **Tokens / MCP** การลบมีผลทันที token จะหายไปจากระบบและกู้คืนไม่ได้
- ผู้ดูแลระบบ (install admin) เห็นและลบ token ได้ทุกอัน แต่ไม่เห็นตัว token เต็มของใคร
